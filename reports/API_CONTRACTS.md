## 1. Global Transport & Security Policy

1. **Authentication:** All state-changing endpoints require an `Authorization: Bearer <Firebase_ID_Token>` header. Tokens are verified via Firebase Admin SDK.
2. **Anti-Replay Nonce Requirement:** Requests to `/enroll` and `/verify` must provide an unexpired server challenge nonce generated by `/challenge`.
3. **Data Minimization:** Raw facial images are strictly prohibited from being persisted on disk. Only 128-d floating point embeddings or base64 RGB crops intended for ephemeral inference are transmitted.
4. **Zero-PII Disclosure:** Duplicate detection responses strictly return blinded display identifiers (`KLS-xK9***wXy-7890`) and masked phone numbers (`+91 ****7890`).

## 2. API Endpoints Specification

### 2.1 Request Cryptographic Challenge Nonce
- **Route:** `POST /api/biometrics/challenge`
- **Purpose:** Issues a single-use cryptographically random nonce bound to caller's UID.
- **Request Body:**
  ```json
  {
    "action": "enroll"
  }
  ```
- **Response (200 OK):**
  ```json
  {
    "success": true,
    "status": "challenge_issued",
    "data": {
      "nonce": "chal_0b060dd3e20e8b2f90a1",
      "expiresAt": 1792683000000,
      "ttlMs": 120000
    },
    "serverTimestamp": "2026-10-22T14:30:00.000Z"
  }
  ```

### 2.2 Server-Authoritative 1:N Enrollment & Duplicate Screening
- **Route:** `POST /api/biometrics/enroll`
- **Purpose:** Screens probe face against entire gallery ($N$ users), enrolls template if unique, or intercepts duplicate.
- **Request Body:**
  ```json
  {
    "nonce": "chal_0b060dd3e20e8b2f90a1",
    "requestHash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
    "probeVector": [0.0384, -0.0912, 0.0411, "...128 floats..."],
    "imageBase64": "...optional ephemeral 112x112 JPEG...",
    "dpdpaConsentVersion": "v1.0_2026",
    "deviceTelemetry": {
      "ipdPixels": 104.5,
      "laplacianVariance": 348.2,
      "blinkDetected": true
    }
  }
  ```
- **Response (200 OK - Approved Unique Identity):**
  ```json
  {
    "success": true,
    "status": "enrolled",
    "data": {
      "isApproved": true,
      "isDuplicate": false,
      "isPendingReview": false,
  ```

- **Response (200 OK - Duplicate Intercepted):**

### 2.3 One-to-One (1:1) Authentication Verification
- **Route:** `POST /api/biometrics/verify`
- **Purpose:** Verifies live probe face against requester's own enrolled template.
- **Request Body:**
  ```json
  {
    "nonce": "chal_fa8901b2c45e",
    "requestHash": "7f83b1657ff1fc53b92dc18148a1d65dfc2d4b1fa3d677284addd200126d9069",
    "probeVector": [0.0381, -0.0915, 0.0409, "...128 floats..."]
  }
  ```
- **Response (200 OK - Match Success):**
  ```json
  {
    "success": true,
    "status": "verified",
    "data": {
      "isMatch": true,
      "similarity": 0.938,
      "threshold": 0.380
    },
    "serverTimestamp": "2026-10-22T14:30:05.100Z"
  }
  ```

### 2.4 Cross-Account 1:N Duplicate Probe
- **Route:** `POST /api/biometrics/cross-account-check`
- **Purpose:** Scans probe face against all enrolled templates *excluding requester's own UID* at login to detect multi-account fraud.
- **Request Body:**
  ```json
  {
    "embeddingBase64": "...base64 encoded 128 float32 array..."
  }
  ```
- **Response (200 OK):**
  ```json
  {
    "success": true,
    "status": "no_match",
    "data": {
      "isDuplicate": false,
      "isHardBlock": false,
      "topSimilarity": 0.214
    },
    "serverTimestamp": "2026-10-22T14:30:06.200Z"
  }
  ```

### 2.6 Biometric Right to Erasure (DPDPA 2023 §12)
- **Route:** `DELETE /api/biometrics/delete`
- **Purpose:** Cryptographically erases user's biometric template and resets verification flags.
- **Response (200 OK):**
