Geo-Search Algorithm

// Bounding Box Calculation final latDelta = radiusKm / 111.0; final lngDelta = radiusKm / (111.0 * cos(lat * pi / 180)); // Firestore Query (Composite Index) db.collection('users') .where('role', isEqualTo: 'worker') .where('accountStatus', isEqualTo: 'approved') .where('isAvailable', isEqualTo: true) .where('discoveryLat', isGreaterThanOrEqualTo: minLat, isLessThanOrEqualTo: maxLat) .limit(200); // Haversine Client Filter Geolocator.distanceBetween( hirerLat, hirerLng, wLat, wLng);

Firestore Security Rules — Branch Architecture

Branch 1
Normal profile update — blocks accountStatus, role escalation, discovery fields unless approved
Branch 2A/2B
pending_profile → pending_face transition + hirer fast-approval path
Branch 2C/2D
Worker/hirer face verification: pending_face → pending_review/approved with faceVerified=true
Branch 3
Hirer can update worker booking fields only — scope-limited write access

Problem Statement

Over 4 crore unorganised labourers in Karnataka have no digital presence. Hirers spend hours calling contacts to find a painter, plumber, or mason in their taluk. No existing platform offers:

  • Kannada voice interface for hirers with low digital literacy
  • Taluk-level geo-discovery (not just city-level)
  • Face-verified worker trust layer
  • Real-time GPS tracking of worker arrival
💡

Key Novelty / Contributions

  • Firestore Geo-Search without Geohash: Lat bounding-box + composite index → haversine filter. No external geohash package.
  • Bilingual Voice AI: Groq NLU for Kannada → Gemini Live → Sarvam TTS pipeline. Handles dialect variations (Malnad, Coastal, North Karnataka).
  • One-shot Voice Booking: "book nearby painter" → search + rank + BookingService.createDirectBooking() in one utterance.
  • Freshness-aware ranking: GPS heartbeat freshness (fresh/recent/stale) factored into worker ranking score.
📐

Composite Ranking Algorithm

// Worker Ranking Score (0–1) score = (0.40 × distScore) + (0.25 × verifWeight) + (0.20 × jobsScore) + (0.15 × ratingScore) // distScore: proximity reward distScore = max(0, 1 - dist/radius) // verifWeight by verification level practicalVerified → 0.70 faceVerified → 0.50 none → 0.30 // jobsScore: experience signal jobsScore = min(1.0, totalJobs / 50.0)
🗂️

Firestore Composite Indexes — Geo-Query Optimization

INDEX 1 — Nearby Search
role ASC accountStatus ASC isAvailable ASC discoveryLat ASC → Used by _searchNearby() → Reduces scan from 2,314 → ~50 docs
INDEX 2 — Area Search
role ASC accountStatus ASC isAvailable ASC district ASC + taluk ASC rating DESC → Used by _searchArea() → O(1) district lookup
