# KELASAGARA BIOMATCH V7: RISK REGISTER

**Document ID:** `RR-BIOMATCH-V7-001`  
**Phase:** Phase 6 (Liveness, Presentation-Attack and Injection-Attack Defense)  
**As-of Date:** 2026-10-10  
**Current Branch:** `biomatch/v7-hardening`  
**Active RRL:** **RRL-0 (Research Prototype)**  

---

| Risk ID | Description | Severity | Likelihood | Impact | Current Mitigation / Status | Evidence IDs |
|---|---|---|---|---|---|---|
| **RISK-01** | **Client Forged Biometric Approval via Firestore Rules:** `firestore.rules` (Branches 2C & 2D) permitted client writes to `faceVerified=true`. An attacker could spoof approval without facial verification. | **CRITICAL** | HIGH | Complete authentication bypass | **RESOLVED & VERIFIED.** Branches 2C & 2D removed from `firestore.rules`. Tested live on Firestore emulator: client update attempting `faceVerified=true` is rejected with HTTP 403. Only server Admin SDK can advance status. | EV-008, EV-011, EV-013 |
| **RISK-02** | **Firebase Spark Read Quota Exhaustion:** 1:N flat kNN vector searches incur reads proportional to gallery size ($E$). At 1,000 users, 50 daily enrollments could consume $1,000 \times 50 = 50,000$ reads, exhausting the Spark daily quota. | **HIGH** | MEDIUM | Service denial for entire application | Bounded candidate search ($K \le 500$) enforced in `FirestoreBiometricRepository`. In-memory sliding counter degrades to asynchronous queue at 85% daily quota. (Invariant I-19, I-27). | EV-004, EV-019 |
| **RISK-03** | **Uncalibrated / Untrained Model Weights:** The ONNX model in `backend/models/kelasagara_mobilefacenet.onnx` was exported from random PyTorch initialization without dataset training. Flutter client uses heuristic Fourier positional landmarks. | **HIGH** | HIGH | Poor real-world recognition accuracy (high FAR/FRR) | **MITIGATED IN CODE.** Forensic audit confirmed Defect ML-001 in `train_mobilefacenet.py` (dummy loop saved random init weights). Model registered as `RESEARCH_ONLY`; `clearedForAutomatedApproval: false` strictly enforced in code and tests. Unique enrollments resolve to `PENDING_REVIEW`. Automated clearance impossible until calibrated checkpoint deployed. | EV-006, EV-007, EV-014, EV-024 |
| **RISK-04** | **Host Machine Lacks Java Runtime:** macOS host lacked Java runtime environment, preventing execution of `firebase emulators:start` for the Firestore local emulator. | **MEDIUM** | HIGH | Blocks local emulator integration testing | **RESOLVED.** OpenJDK 27 installed via Homebrew (`/opt/homebrew/opt/openjdk`). Local Firestore Emulator executes headlessly and runs rules test suite cleanly. | EV-002, EV-013 |
| **RISK-05** | **Demographic Calibration Gap:** The 0.74 cosine similarity duplicate threshold is a literature baseline, not empirically tuned on consented Indian faces across varying lighting and camera sensors. | **MEDIUM** | MEDIUM | Increased False Match or False Reject rates | Tri-state classification adopted: Borderline cases (0.65 to 0.74) route to manual review rather than hard rejection (ADR-005). All enrollments currently route to `PENDING_REVIEW` under RRL-0. Formal calibration protocol authored in `CALIBRATION_PROTOCOL.md`. | EV-004, EV-014, EV-028, EV-030 |
| **RISK-06** | **Presentation / Injection Attack Vulnerability:** EAR blink detection does not defend against high-speed digital video injection, virtual camera drivers, or deepfake video streams. | **HIGH** | MEDIUM | Sybil duplicate account creation via virtual camera injection | **MITIGATED & TESTED.** Two-track defense (R-13) implemented. Session challenge-response nonce with 60s TTL implemented in `SessionChallengeService` and verified in red-team suite (`test_liveness_injection_bypass.test.ts`). Replay attacks, cross-user theft, and cross-action reuse mathematically prevented (Invariants I-04, I-05, I-21). Appendix G matrix complete. | EV-005, EV-018, EV-032, EV-033, EV-035, EV-036 |
| **RISK-07** | **Spark Read Quota Saturation Under Unpartitioned Flat Vector Scans ($N \ge 10,000$):** At 10,000 users, an unpartitioned 1:N scan incurs 105 reads per query; 142 enrollments completely exhausts Spark budget. | **HIGH** | MEDIUM | Application-wide HTTP 429 quota exhaustion | Enforced bounded candidate scan ($K \le 500$); limits query read cost to 10 reads regardless of gallery size $N$. Detailed in `QUOTA_WORKSHEET.md`. | EV-019 |
| **RISK-08** | **Face Template Inversion Vulnerability (R-14):** Mathematical feature vectors (128-D float32) are theoretically invertible back to reconstructed facial portraits using neural decoders. | **HIGH** | LOW | Biometric privacy breach if raw vectors leak | Per-subject envelope encryption (AES-256-GCM) with random salt; raw vectors never returned by any API; direct client reads blocked by `firestore.rules`. Crypto-shredding on deletion. | EV-013, EV-018 |
| **RISK-09** | **API Oracle Probing & Parameter Enumeration:** Scripted attackers probe the registration API with variations of a victim's photograph to infer if the victim has a registered profile. | **MEDIUM** | MEDIUM | User enumeration / privacy leakage | **MITIGATED & TESTED.** Uniform response contract (`UniformBiometricApiResponse`), minimum latency padding ($\ge 150\text{ms}$ on all outcomes including 404), and per-IP rate limiting (60 req/min) enforced (Invariants I-08, I-23). Verified live. | EV-004, EV-018, EV-043, EV-044 |
| **RISK-10** | **Play Integrity Standard Quota Saturation:** Exceeding 10,000 daily verdict calls as active user base grows. | **MEDIUM** | LOW | Attestation failures for legitimate clients | In-app token caching (1-hour TTL) for non-sensitive app actions; reserve un-cached tokens for biometric enrollment sessions and work completions. Quota tier increase plan documented. | EV-019 |
| **RISK-11** | **Upstream Training Data Copyright Contamination:** Pretrained candidate weights (SFace trained on CASIA-WebFace; YuNet trained on WIDER FACE) originate from academic datasets with non-commercial restrictions. | **HIGH** | HIGH | Legal takedown / commercial copyright liability | Models tagged as `RESEARCH_ONLY`. Path P-B (DigiFace-1M synthetic dataset + consented Indian faces) established as target production roadmap. | EV-021, EV-022 |
| **RISK-12** | **INT8 Quantization Calibration Distortion:** Post-training quantization calibrated on random uniform noise instead of real face images (Defect ML-002) severely degrades convolutional activation ranges. | **HIGH** | MEDIUM | Catastrophic precision loss in edge mobile inference | Mandate representative calibration set of $\ge 200$ real preprocessed face images prior to TFLite INT8 deployment. Server FP32 remains gold standard. | EV-024, EV-027 |
| **RISK-13** | **Concurrent Enrollment Duplicate Race Condition:** Two simultaneous registrations with the same face execute vector screening concurrently before either template is committed, causing both to be accepted. | **CRITICAL** | MEDIUM | Dual active accounts bypassing duplicate screening | **MITIGATED & TESTED.** Solved via Pending-Inclusive screening and monotonic lease timestamps (Invariant I-12). Concurrency test suite proves exactly one account activates; losing session is rejected. | EV-037 |
| **RISK-14** | **Database Platform Drift & Scope Creep:** Introducing external vector databases (PostgreSQL/pgvector, Qdrant, Milvus) violates the zero-billing Spark constraint and ADR-001 single database architecture. | **HIGH** | HIGH | Platform violation and unmaintainable infrastructure drift | **RESOLVED & FORMALIZED.** Evaluated 7 candidates in `STORE_DECISION.md`; disqualified all external databases. Candidate G (Cloud Firestore `asia-south1` + in-memory bounded cache) formally locked. | EV-038 |
| **RISK-15** | **Split-Brain User/Vault Desynchronization:** Asynchronous crashes or unauthorized edits could create rogue `faceVerified=true` states without vault templates or orphaned vault templates. | **CRITICAL** | LOW | Unverified accounts gaining platform access or template leaks | **MITIGATED & TESTED.** Solved via atomic batch writes (Invariant I-14) and `EnrollmentStateMachine.reconcileState` (Invariant I-16). Automated fail-closed self-healing revokes rogue approvals. | EV-039, EV-041 |
| **RISK-16** | **Audit Log Repudiation & Modification:** Privileged malicious actors or compromised service credentials could tamper with or delete incriminating duplicate interception records. | **HIGH** | LOW | Loss of regulatory auditability and forensic traceability | **MITIGATED & TESTED.** Implemented cryptographic SHA-256 recursive hash chaining in `TamperEvidentAuditService` (Invariant I-17). Field tampering, deletion, or reordering breaks the chain and is immediately detected. | EV-040, EV-041 |
| **RISK-17** | **Unauthenticated Probe Injection & Nonce Theft:** Adversaries submit precomputed vectors directly to `/verify-1to1` or `/enroll` without fresh live sensor interaction. | **HIGH** | MEDIUM | Synthetic biometric injection bypass | **MITIGATED & TESTED.** Enforced 60s single-use cryptographic challenge nonces bound to UID and action type (`SessionChallengeService`). Cross-action, cross-user, or replayed nonces rejected with HTTP 403 (Invariants I-04, I-05). | EV-043, EV-044 |
| **RISK-18** | **Cold-Start Graph Latency Spikes:** Dynamic loading of the ONNX inference graph on cold restarts incurs a 500ms–2000ms latency hit on initial user registration requests. | **MEDIUM** | HIGH | Degraded initial onboarding latency / client timeouts | **MITIGATED & TESTED.** `InferenceRedundancyService` performs background cold-start graph warmup (preloads ONNX session and executes synthetic forward pass on init, verified 82ms). Eliminates runtime graph compile penalty. | EV-046, EV-047, EV-048 |
| **RISK-19** | **Cross-Model Biometric Vector Contamination:** Templates extracted under different neural architectures (MobileFaceNet vs SFace) reside in incompatible embedding spaces. Direct cosine comparison produces meaningless random similarities. | **HIGH** | MEDIUM | Erroneous duplicate rejections or false matches across model migrations | **MITIGATED & TESTED.** Multi-model gallery compatibility check (`checkModelCompatibility()`) and model-versioned gallery indexing strictly block cross-model cosine comparison (fail-closed with error `MODEL_INCOMPATIBLE`). | EV-046, EV-047, EV-048 |
